# 0033. Provider configuration, credentials we refuse, and the disclosure before an external provider

- Status: accepted
- Date: 2026-10-05
- Principle or guide served (or deviated from): P5 (configuration through the environment, secrets never in files or code), P8 (degradation visible: `providers` lists what is configured), brief §2 (no subscription OAuth, no Copilot), [CONSIDERATIONS §1](../legal/CONSIDERATIONS.md#1-model-provider-terms-what-we-may-and-may-not-support), [threat model T-20](../security/THREAT-MODEL.md) (third-party disclosure to the AI provider), `security-review` (secrets, errors)

## Context

The transcript goes to whichever provider the user configures. Three things must therefore be decided: where settings and keys may come from, which credentials must be refused, and what the user is told and asked before the first external call.

## Decision

**Precedence** (one resolver, `ProviderConfigResolver`): command-line flag, then environment variable, then the user config file, then the built-in default. Provider and model have no default (model ids change; none is hardcoded). Environment variables: `EXIT_INTERVIEW_PROVIDER`, `_MODEL`, `_BASE_URL`, `_API_KEY_ENV`, `_CONFIG`, `_CONFIG_DIR`, `_TIMEOUT_SECONDS`, `_MAX_RETRIES`, `_MAX_TOKENS`, `_PRICE_INPUT_PER_MTOK`, `_PRICE_OUTPUT_PER_MTOK`, `_MAX_COST`, `_NUM_CTX`, plus `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OLLAMA_HOST`. The generic base-URL variable wins over a provider-specific one. `ANTHROPIC_BASE_URL` is deliberately **not** read: a gateway URL left in a shell by another tool should not silently receive a transcript.

**Keys**: only from environment variables. There is **no `--api-key` flag** (shell history, process listings). `--api-key-env NAME` / `EXIT_INTERVIEW_API_KEY_ENV` / `apiKeyEnv` name the variable (validated as a variable name, so a pasted key is rejected without being echoed). The **config file may not contain a key**: a property such as `apiKey`, `token` or `password` is refused with a message pointing to `apiKeyEnv` (files end up in backups and dotfile repositories). Keys are held in `SecretString` (fixed placeholder `ToString`, no serialization); no exception message, log line, span, metric label or the preference file carries one (canary tests).

**Base URLs** (`BaseUrlPolicy`): absolute `http`/`https`; **no embedded credentials** (refused, and the message never repeats the URL); no query or fragment; plain `http` only for a loopback host or when no key is sent; the production transport follows no redirects (a 3xx is refused), so a key header cannot be forwarded to another host. A base URL on `githubcopilot.com` is refused (hostname from general knowledge, **not verified**; the guard keeps "no Copilot adapter" from being bypassed).

**Refusals** (the brief's non-goals, enforced and explained):

- *Claude subscription credentials.* The refusal rests only on what Anthropic's documentation states, read 2026-10-05: [Authentication](https://code.claude.com/docs/en/authentication) says `CLAUDE_CODE_OAUTH_TOKEN` is "a long-lived OAuth token generated by `claude setup-token`" that "authenticates with your Claude subscription" (and the env-vars page lists `CLAUDE_CODE_OAUTH_REFRESH_TOKEN`); [legal and compliance](https://code.claude.com/docs/en/legal-and-compliance) says Anthropic "does not permit third-party developers ... to route requests through Free, Pro, or Max plan credentials". So: naming `CLAUDE_CODE_OAUTH_TOKEN` or `CLAUDE_CODE_OAUTH_REFRESH_TOKEN` as the key source (flag, environment or file) is refused with a message pointing to the README; provider ids such as `claude-subscription`, `claude-max` or `claude-ai` are refused; when the Anthropic key is missing and such a variable is present, the message says it "is not read and is not supported". **There is no value-based heuristic**: none of the pages read describes a recognisable prefix or format for subscription tokens (a search of the fetched pages for `sk-ant-` found nothing), so inventing one would be a guess. Limit, stated in the README: a subscription token pasted into `ANTHROPIC_API_KEY` cannot be recognised here and is left to the API to reject.
- *GitHub Copilot.* No adapter, no provider id (`copilot`, `github-copilot`, ... are refused with: "a decision, not a finding that it is prohibited: the terms ... could not be verified"), as the brief and CONSIDERATIONS row 5 require.

**Disclosure** (`Disclosure`, `ConfirmationStore`, the CLI): before the first interview with an **external** provider (anything not on a loopback address, so a remote Ollama counts) the CLI prints a plain-language notice (what is sent: every question and answer; to whom: provider and host, "using your own API key"; under whose terms: the provider's, "not controlled and not verified" by this project; that it is not sent to us, stays in memory and is not saved unless `--save-transcript`; that the record is not submitted by this version; Ctrl-C/Ctrl-D discards; the local-model alternative; the README link) and requires typing `yes`. End of input counts as no. `--yes-i-understand` confirms without a prompt (for scripts) and persists nothing. A **local** model gets a shorter notice and no prompt (a local OpenAI-compatible gateway additionally gets "may itself forward requests to a remote provider"; the weights' own licence is mentioned). The only thing persisted is a small preference file the user can delete (`confirmations.json` in the config directory, created with owner-only permissions on Unix): provider id, host and notice version, nothing else (no key, model, time or content), and only if the user answers `y` to "Remember this choice?". `exit-interview providers forget-confirmations` deletes it; a corrupt file counts as empty.

**Visibility**: `exit-interview providers` lists every provider, whether its key variable is set (never its value), the config file location, the remembered confirmations, the variables read and the effective selection with where each value came from, with no network call.

## Consequences

- A user can run without any file (flags and `ANTHROPIC_API_KEY`), with a file (no secrets in it), or from scripts (`--yes-i-understand`).
- The notice asserts nothing about a provider's retention or training policy: CONSIDERATIONS rows 2c and 3 are not fully verified, so it says the project "has not verified them for your account".
- The notice and the confirmation are a transparency measure for the person running the tool; they are not consent for anyone else and do not make a real interview lawful ([legal §4](../legal/CONSIDERATIONS.md#4-why-real-interviews-are-out-of-scope) still applies; the README says so).
- Trigger to revisit: Anthropic documenting a recognisable subscription-token format (then a value check can be added), or GitHub's terms being read.
