# UI audit, 2026-10-11

Audit of the portal and the `/interview` page on current `main` (`fefa9eb`), walked end to end with the production build
against the e2e stub. Every screenshot is a full-page capture of a state the stub can produce; nothing was changed in product code.

**Scope and method.** 28 states at 1280×800 and 390×844 (56 PNGs, all under 250 KB). Captures were made by a Playwright script
(not committed) that drove each state with a fresh account. Each run also recorded the page `lang`, horizontal overflow, alert
text, console errors and the keyboard tab order on `/interview`. **Not run:** axe, a contrast measurement, a screen reader, a
keyboard-only pass beyond one tab sequence, Polish-language screens, a 200% zoom check, and the `/interview` loading state.
I read the desktop screenshots; the mobile PNGs were checked for horizontal overflow (none found, 0 px on all 28 mobile states)
but I did not review each one visually, so mobile findings below are limited to what the DOM showed.

Note on the commit: the screenshots and findings are from `fefa9eb`. After that, `main` moved to `8bdff9f`, which links `/interview`
from the menu and the home page (the fix from [PR #59](https://github.com/konradcinkusz/exit-interview-agent/pull/59)). The
"no link to `/interview`" findings below describe `fefa9eb`; they were not re-captured on `8bdff9f`.

## (a) The former employee's journey today

Someone who was let go and wants to give an exit interview lands on a page that opens with "An open-source AI agent that runs a
structured exit interview" and a yellow-red "Development build … simulated interviews only" banner, then reads a list headed
"What this is not … Not for real people yet". The primary call to action is "Connect your AI client", which assumes they run
Claude and want to wire a connector. On `fefa9eb` they had to find the interview on their own: nothing on the home page or in the menu
linked to `/interview`, so the feature was invisible (`main` has since added the link). A signed-in user who does find it gets a start form that says
"Interview credits you have: 1", spends that credit on Continue, reads a long consent list, and chats. At the end they see a
record and draft "Glassdoor / Google review / Reddit" texts with a warning stacked on a warning. Then they have 0 credits and the
"Buy one interview" button leads to a payment page that does not work on the local stack, so a local user is stuck. The journey
works end to end once it is found, but it is wrapped in developer-facing wording and in navigation that a former employee does
not need.

**Cross-cutting findings**

- **Language.** Every page except `/interview` is English (`lang="en"`). The interview page sets `lang` from the browser (`en` in the run) and offers Polish, but the English-only portal around it breaks the flow for a Polish-speaking owner. Not verified: the Polish screens themselves.
- **Development notice.** "Development build: simulated interviews only…" appears on the home page (twice), in every footer, and in the interview result copy. For a former employee this reads as "this does not really work". It should be a single footer line, and the wording "Not for real people yet" should go.
- **Contrast, focus, and spacing.** Not measured (no axe, no contrast tool was run). Visually the interview start screen uses native form controls, which do not match the site's buttons.
- **Keyboard.** Tab order on `/interview` start was checked: skip link, seven header links, language radio, tenure select, Continue, Buy. The seven header links come before the form, so a keyboard user must tab through the whole developer-oriented menu to reach the interview.
- **Mobile.** No horizontal overflow on any of the 28 mobile states (scroll width equal to client width). Visual mobile review was not completed.
- **Loading and error states.** The interview credit line shows "Checking your credits…" while loading, which was not captured. The generic error page (`error.tsx`) could not be reached from the UI without code changes and was not captured.

## (c) Proposed target journey for the former employee (six steps)

1. **Land** (`/`): one headline ("Give your exit interview with an AI"), one primary button ("Start" → sign in or create an account), one line on what is stored and what is not. The development notice appears once, in the footer. No menu items for developer tools.
2. **Sign up or sign in**: a sign-in page that says "to start your exit interview", then the consent step only if the terms changed, with the changed document first. After sign-in, go straight to `/interview`.
3. **Start** (`/interview`): language, time at the company, and a single status line ("1 interview ready" or "0 interviews: get one"). Continue is the primary button. When there is no credit, the button says what the next step is, and a dev-only test credit exists in local builds only.
4. **Chat**: a progress line, "Send" as the only primary button, "Finish interview" (keeps the record) and "Stop and delete" (deletes, with a confirmation dialog). Errors keep the typed answer and say what to do next.
5. **Result**: one warning (drafts are not facts), the record in sentences with "Not discussed" topics collapsed, the draft cards with Copy, one "Save" control for downloads, and a clear statement of how long the result stays readable.
6. **Delete** (from the result, or any time during the interview): a dialog with Cancel first, a plain "The interview and everything from it is deleted. Nothing is kept." and a return to start that explains what happened to the credit.

## (d) The ten changes that would help most, in priority order

1. **Make the interview the primary call to action for signed-in users.** The menu and home links landed on `main` in `8bdff9f` (PR #59); the home page still offers no interview CTA.
2. **Cut the navigation for this audience**: remove "Connect your AI client", "Use the command line", "Employer signals" and "Delete a submission" from the primary header; keep them in the footer.
3. **Rewrite the home page for the former employee** ("Give your exit interview with an AI"); move the open-source and developer description below it.
4. **Show the development notice once**, in the footer, and remove "Not for real people yet" and the duplicate banner.
5. **Fix the no-credit dead end**: explain the disabled Continue, and make the local stack give a dev-only test credit so the flow can be completed.
6. **Add "Finish interview" to the chat**, separate from "Stop and delete", with a progress line.
7. **Simplify the result screen**: one warning, collapsed "Not discussed" topics, a single Save control, a plain explanation of dropped texts.
8. **Use a real confirmation dialog** for deletion (focus trap, Cancel first) and state the credit outcome after deletion.
9. **Restyle the interview form controls** to match the site (select, radio, buttons) and make the credit line a status, not grey text.
10. **Run axe and a contrast check on every state** and fix what they find, and capture the Polish screens so the language choice is reviewed too.
